หลักการจัดลำดับ: Phase 0 คือ MVP บางที่สุดที่ยังครบ flow หลัก "สแกน QR → ดูเมนู → สั่งออเดอร์ → ออเดอร์ไปถึงครัว/แจ้งเตือน → จ่ายเงินจบบิล" ได้จริงโดยไม่มีพนักงานมารับออเดอร์ที่โต๊ะ ทั้งช่องทางโต๊ะ (dine-in) และเคาน์เตอร์ (takeaway) ฟีเจอร์เสริม (ตัวเลือกสินค้า, ใบเสร็จ, รายงาน, หลายภาษา, จ่ายเงินออนไลน์สำหรับ dine-in) เลื่อนไป Phase ถัดไปทั้งหมด ยกเว้น loyalty stamp card ที่เลื่อนมาอยู่ Phase 1 แล้ว

---

## Phase 0 — MVP (ต้องมีก่อนเปิดร้านจริง)

เป้าหมาย: ลูกค้านั่งโต๊ะหรือยืนหน้าเคาน์เตอร์ สแกน QR สั่งเองได้ครบ ไม่ต้องมีพนักงานมารับออเดอร์เลย ครัวเห็นออเดอร์และอัปเดตสถานะได้ แคชเชียร์ปิดบิล/ยืนยันรับชำระเงินได้ แอดมินตั้งเมนู/QR เองได้

| ID | เรื่อง | Actor |
|---|---|---|
| US-01 | สแกน QR เข้าสู่ระบบสั่งอาหารของโต๊ะ | ลูกค้า |
| US-02 | ดูเมนูสินค้า | ลูกค้า |
| US-03 | จัดการตะกร้าสินค้า | ลูกค้า |
| US-04 | ยืนยันส่งออเดอร์เข้าครัว | ลูกค้า |
| US-05 | ติดตามสถานะออเดอร์ | ลูกค้า |
| US-06 | สั่งเพิ่มได้หลายรอบในโต๊ะเดียวกัน | ลูกค้า |
| US-07 | ดูสรุปยอดรวมของโต๊ะก่อนจ่ายเงิน | ลูกค้า |
| US-13 | เห็นออเดอร์ใหม่แบบเรียลไทม์ | ครัว/บาร์ |
| US-14 | อัปเดตสถานะออเดอร์ | ครัว/บาร์ |
| US-15 | แจ้งเตือนเมื่อมีออเดอร์ใหม่ | ครัว/บาร์ |
| US-16 | ทำเครื่องหมายสินค้าหมดชั่วคราว | ครัว/บาร์ |
| US-18 | ดูสรุปยอดที่ต้องเรียกเก็บต่อโต๊ะ | แคชเชียร์ |
| US-19 | ปิดบิลและเคลียร์โต๊ะ | แคชเชียร์ |
| US-20 | ยกเลิกออเดอร์/รายการ | แคชเชียร์ |
| US-23 | จัดการเมนู | แอดมิน |
| US-24 | สร้าง QR code ผูกกับแต่ละโต๊ะ | แอดมิน |
| US-28 | สั่งแบบซื้อกลับผ่าน QR หน้าเคาน์เตอร์ (Takeaway) | ลูกค้า |
| US-29 | ยืนยันรับชำระเงินสำหรับออเดอร์ซื้อกลับ (Takeaway) | แคชเชียร์ |

**Exit criteria ของ Phase 0:** ลูกค้าจริงในร้านสามารถสแกน QR แล้วสั่ง-รับ-จ่ายเงินจบ 1 รอบการนั่งโต๊ะได้ โดยไม่มีพนักงานมารับออเดอร์ที่โต๊ะเลยแม้แต่ครั้งเดียว **และ** ลูกค้าที่มาซื้อกลับสามารถสแกน QR เคาน์เตอร์ สั่ง จ่ายเงินก่อน แล้วรอรับของได้ครบ โดยไม่ต้องบอกพนักงานปากเปล่าเช่นกัน

## Phase 1 — เสริมความลื่นไหลของหน้าร้าน (หลัง MVP นิ่งแล้ว)

เป้าหมาย: ลดความคลาดเคลื่อนของออเดอร์ (ตัวเลือก/หมายเหตุ) เติมเครื่องมือหลังบ้านที่ร้านจริงต้องใช้ทุกวัน (ใบเสร็จ, คืนเงิน, รายงาน) และเริ่มสร้างความผูกพันลูกค้าประจำด้วย loyalty stamp card

| ID | เรื่อง | Actor |
|---|---|---|
| US-08 | เลือกตัวเลือกเสริมของสินค้า | ลูกค้า |
| US-09 | ใส่หมายเหตุพิเศษต่อรายการ | ลูกค้า |
| US-11 | สะสมแต้มแบบบัตรปั๊ม (Stamp Card) — ซื้อครบ 10 แถมฟรี 1 | ลูกค้า |
| US-17 | ดูประวัติออเดอร์ย้อนหลังของกะ | ครัว/บาร์ |
| US-21 | ออกใบเสร็จ | แคชเชียร์ |
| US-22 | คืนเงิน | แคชเชียร์ |
| US-25 | ดูรายงานยอดขาย | แอดมิน |
| US-26 | เปิด/ปิดรับออเดอร์ของร้าน | แอดมิน |

**หมายเหตุ:** US-11 ย้ายมาจาก Phase 2 เดิม (ดูเหตุผลใน [[../01-spec/product-backlog-v1|01-spec/product-backlog-v1]] หัวข้อ US-11) — ต้องมี consent-capture step ในระบบสั่งอาหารก่อนเริ่มสะสมแต้ม

## Phase 2 — เติบโต/สร้างความผูกพันลูกค้า (ทำเมื่อร้านเดินเครื่องคล่องแล้ว)

เป้าหมาย: ฟีเจอร์ที่เพิ่มรายได้/ลดงานแอดมินระยะยาว ไม่กระทบการเปิดร้านวันแรก

| ID | เรื่อง | Actor |
|---|---|---|
| US-10 | เลือกภาษาเมนู | ลูกค้า |
| US-12 | ชำระเงินออนไลน์ผ่าน QR ก่อนออเดอร์เข้าครัว (dine-in) | ลูกค้า |
| US-27 | จัดการผู้ใช้งานพนักงาน/สิทธิ์การเข้าถึง | แอดมิน |
