กลับไปที่ [[index|02-plan]]

หลักการจัดลำดับ: Phase 0 คือ MVP บางที่สุดที่ยังครบ flow หลัก "สแกน QR → ดูเมนู → สั่งออเดอร์ → ออเดอร์ไปถึงครัว/แจ้งเตือน → จ่ายเงินจบบิล" ได้จริงโดยไม่มีพนักงานมารับออเดอร์ที่โต๊ะ ทั้งช่องทางโต๊ะ (dine-in) และเคาน์เตอร์ (takeaway) พร้อมตัวเลือกระดับการคั่ว/เมล็ดพิเศษที่เป็นแก่นของกาแฟเอง ฟีเจอร์เสริม (ตัวเลือกสินค้าอื่นที่ไม่ใช่คั่ว/เมล็ด, ใบเสร็จ, รายงาน, หลายภาษา, จ่ายเงินออนไลน์สำหรับ dine-in, multi-station) เลื่อนไป Phase ถัดไปทั้งหมด ยกเว้น loyalty stamp card ที่เลื่อนมาอยู่ Phase 1 แล้ว — สำหรับ Phase 0 พนักงานฝั่งร้าน (ครัว/บาร์ + แคชเชียร์) เป็น**บทบาทเดียว**สำหรับร้านนี้ (ดู Business Rule ข้อ 13)

## Phase 0 — MVP (ต้องมีก่อนเปิดร้านจริง)

เป้าหมาย: ลูกค้านั่งโต๊ะหรือยืนหน้าเคาน์เตอร์ สแกน QR สั่งเองได้ครบ ไม่ต้องมีพนักงานมารับออเดอร์เลย พนักงานแคชเชียร์/หน้าร้าน (บทบาทรวม เตรียมของ+การเงิน สำหรับร้านนี้) เห็นออเดอร์ อัปเดตสถานะ ปิดบิล/ยืนยันรับชำระเงินได้ในหน้าจอเดียว แอดมินตั้งเมนู/QR เองได้

## Phase 1 — เสริมความลื่นไหลของหน้าร้าน (หลัง MVP นิ่งแล้ว)

เป้าหมาย: ลดความคลาดเคลื่อนของออเดอร์ (ตัวเลือก/หมายเหตุ) เติมเครื่องมือหลังบ้านที่ร้านจริงต้องใช้ทุกวัน (ใบเสร็จ, คืนเงิน, รายงาน) และเริ่มสร้างความผูกพันลูกค้าประจำด้วย loyalty stamp card

## หมายเหตุการส่งต่อ

Phase 0 พร้อมส่งต่อให้ COULSON เริ่ม `02-design` ได้ทันที (architecture, DB schema, prototype) — ดู task breakdown ที่ [[../03-task/mvp-task-breakdown-v1|03-task/mvp-task-breakdown-v1]]

**อัปเดต (รอบ feedback ที่ 5) — สโคปของ Phase 0 เล็กลงจริง:** เดิม US-13-16 (เดิมคือ "ครัว/บาร์") ถูกวางแผนให้เป็นหน้าจอ/อุปกรณ์แยกต่างหากจากหน้าจอแคชเชียร์ (US-18-20) เพราะสมมติว่าเป็นคนละ actor ตอนนี้ยืนยันแล้วว่าร้านนี้เป็นสถานีเดียว คนเดียวกันทำทั้งสองหน้าที่ — **COULSON จึงออกแบบเป็น UI เดียว ไม่ต้องแยก 2 หน้าจอ/2 อุปกรณ์อีกต่อไปสำหรับ Phase 0** ลดงานออกแบบและงานพัฒนาลงจริง (ไม่ใช่แค่เปลี่ยนชื่อ actor) — ดูรายละเอียดที่ [[../03-task/mvp-task-breakdown-v1|03-task/mvp-task-breakdown-v1]]

Phase 1/2 ยังไม่ต้องออกแบบตอนนี้ แต่ควรระวังไม่ให้ดีไซน์ของ Phase 0 ปิดทางขยายไปทำ Phase 1/2 ทีหลัง (เช่น data model ของออเดอร์ควรเผื่อช่องตัวเลือกสินค้า/หมายเหตุไว้ตั้งแต่ต้น แม้ยังไม่เปิดใช้ในหน้าจอ MVP)

**อัปเดต (รอบ feedback ที่ 7):** เพิ่ม US-35/US-36 (ระดับการคั่ว/เมล็ดพิเศษ) เข้า Phase 0 — COULSON ควรสร้าง option-group mechanism ทั่วไป (ไม่ใช่แค่ hardcode 3 ค่าคั่ว) ตั้งแต่ Phase 0 เพื่อให้ Phase 1 (US-08: ความหวาน/น้ำแข็ง/ไซส์) มาต่อยอดง่าย ๆ ทีหลังโดยไม่ต้องรื้อสร้างใหม่
