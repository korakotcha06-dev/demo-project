## 2. ✅ สิ่งที่ยืนยันว่าเราออกแบบมาถูกทาง

1. **แป้น PIN** — mockup ใช้แป้นตัวเลขบนจอ + จุดแสดงจำนวนหลัก **ไม่มีช่องพิมพ์ข้อความ**
   ตรงกับที่ [[../02-technical/architecture-v1|architecture-v1]] §10.3 เตือนเรื่อง password manager
   และตรงกับที่ build ไป — **สองฝ่ายคิดออกมาเหมือนกันโดยไม่ได้เห็นกัน**
2. **ลำดับสถานะ** New → Making → Ready → Complete ตรงกับ `queued → in_progress → ready → completed`
3. **aging ต่อการ์ด** ("3 min ago") ตรงกับที่เก็บ `placed_at`/`status_changed_at` ไว้ตั้งแต่ Phase 0
4. **lime เป็น primary action เดียวต่อการ์ด** ตรงกับกฎ §2 ของ design-system
5. **แยก Dine-in / Takeaway** ที่ระดับบนสุด ตรงกับ BR ข้อ 12

### 6.3 ข้อเท็จจริงของ prototype ที่เอกสารชุดนี้เคยบันทึกไว้ผิด/ไม่ครบ

1. 🔴 **`design-thynacafe.md` §6 เขียนว่า "8 หน้า" แต่มี 9** — ตารางใต้หัวข้อมี 9 แถว และโค้ด prototype
   มี 8 flag (`isAssign/isOrder/isQueue/isPay/isReceipt/isHistory/isManage/isDash`) **บวกหน้า login
   อีกหน้า** = 9 · ยังมีสถานะ `isLoading` (splash) ที่ไม่ถูกนับที่ไหนเลย
2. **มี Option modal** (size / milk / shots / temp) ตอนกดเพิ่มสินค้าจากหน้าสั่ง — ไม่ถูกนับใน "8 หน้า"
   แต่เป็นองค์ประกอบที่ต้องมี · ยืนยันจากภาพที่ Touch ส่ง: บรรทัด "Double shot · Hot" ใต้ชื่อสินค้าในบิล
3. 🔴 **`--r-card` ของ mobile = 24px แต่ของ POS = 32px** — เอกสารไม่ได้แยกให้ชัด
   **ถ้าโค้ดหยิบค่าเดียวไปใช้ทั้งสองฝั่งจะผิดข้างใดข้างหนึ่งแน่นอน** (`tokens.css:55` ปัจจุบันมีค่าเดียว = 32px)
4. `ProductCard` มี prop **`added`** → ปุ่ม + เปลี่ยนเป็น lime เมื่อสินค้านั้นอยู่ในบิลแล้ว

## 8. คำที่ผู้ใช้เห็น — บทเรียนจากคำว่า "ปลดระวาง" (2026-08-23)

Touch ทักว่าคำว่า **"ปลดระวาง"** ที่หน้าจัดการโต๊ะ *"ตลกมาก"* — ถูกต้อง และน่าสนใจ
กว่านั้นคือ **มันขัดกฎที่หน้าจอกลุ่มนี้เขียนกำกับตัวเองไว้อยู่แล้ว**

`admin/layout.tsx` เขียนกติกาข้อ 2 ไว้ว่า **"🔴 ห้ามใช้ศัพท์เทคนิค (schema / database /
ID / slug / coordinate) ในหน้าจอ"** — "ปลดระวาง" ไม่ได้อยู่ในวงเล็บนั้น เพราะมันไม่ใช่
ศัพท์เทคนิค **มันเป็นศัพท์ปลดประจำการเรือรบ/อากาศยาน** ซึ่งแปลกกว่าศัพท์เทคนิคเสียอีก

🔴 **สัญญาณที่มองข้ามไป และควรใช้เป็นเครื่องตรวจต่อจากนี้:** ปุ่ม *ย้อนกลับ* ของการกระทำ
เดียวกันในไฟล์เดียวกันใช้คำว่า **"เอากลับมาใช้"** มาตั้งแต่ต้น — ภาษาปกติ อ่านรู้เรื่อง
**เมื่อคู่ตรงข้ามของคำหนึ่งเป็นภาษาคน แต่ตัวมันเองเป็นศัพท์เฉพาะ นั่นคือคำที่หลุด**
ไม่ต้องรอให้ใครมาทัก

และ mockup ตอบคำถามนี้ไว้แล้วโดยไม่ต้องใช้คำเลย — **ปุ่ม `✕` เปล่า ๆ** ซึ่งอ่านออกว่า
"เอาออก" ทันที · ถ้าไอคอนที่ไม่มีคำยังสื่อได้ดีกว่าคำที่เราเลือก แปลว่าคำนั้นผิด

**แก้แล้ว:** "เอาออก" / "เอาออกจากผัง" / "เอาออกแล้ว" ทุกจุดที่ผู้ใช้เห็น รวมข้อความ error ·
คอลัมน์ `retired_at` และ endpoint `/retire` **ยังชื่อเดิม** — เปลี่ยนแค่คำที่คนอ่าน
ไม่ใช่ชื่อในระบบ
