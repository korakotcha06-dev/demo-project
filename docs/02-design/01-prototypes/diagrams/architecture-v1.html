สาม Surface บน codebase เดียว

ลูกค้า พนักงาน และแอดมิน เข้าคนละ route แต่ใช้โปรเจกต์เดียวกัน ทุกการเขียนลงฐานข้อมูลถูกบังคับให้ผ่าน Route Handler ที่เดียว ส่วนการอ่านสถานะแบบสดวิ่งตรงไปที่ Supabase Realtime เพราะ Vercel เป็น serverless ถือ WebSocket ค้างไม่ได้

THREE PRINCIPLES

หลักที่ผังนี้บังคับ

  • เขียนผ่าน Route Handler เท่านั้น — ไม่มี client ตัวไหนแม้ฝั่งพนักงานเขียน DB ตรง เพราะ BR 4 · BR 11 · BR 12 ต้องอยู่ในทรานแซกชันเดียว
  • อ่านสดไปตรงที่ Realtime — Vercel เป็น serverless ถือ WebSocket ค้างไม่ได้ มี polling 5 วินาทีเป็นทางสำรอง
  • codebase เดียว 3 route group — ไม่ใช่ 3 โปรเจกต์ เพราะ US-30 บังคับให้จอพนักงานใช้ตะกร้าตัวเดียวกับลูกค้า

IDENTITY

ยืนยันตัวตน 2 กลไก แยกโดยเจตนา

  • ลูกค้า — session token ที่ออกจาก QR ไม่มีบัญชี ไม่มีรหัสผ่าน
  • พนักงาน / แอดมิน — Supabase Auth อีเมลและรหัสผ่าน
  • สองกลไกนี้ไม่ปนกัน ทำให้ลูกค้าเข้าถึงหน้าพนักงานไม่ได้แม้เดา URL ถูก

FIDELITY

ต่างจากต้นฉบับตรงไหน

  • 9 node → 7 (เพดาน 9) · 14 เส้น → 7
  • Storage รูปเมนู ตัดทิ้ง — เป็นปลายทางที่ไม่เปลี่ยนเรื่อง
  • Auth ยุบเป็น sublabel ของเครื่องพนักงานและแอดมิน
  • subscribe 3 เส้น รวมเป็นเส้นเดียวกำกับ ×3
