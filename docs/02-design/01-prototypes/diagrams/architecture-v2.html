ARCHITECTURE · §9 · REVISED 2026-08-20

ย้ายมาอยู่บน VPS ของเราเอง

ฐานข้อมูลยังเป็น Postgres เหมือนเดิมทุกประการ เปลี่ยนแค่ว่าใครดูแลมัน ผลที่ตามมาโดยไม่ได้ตั้งใจคือข้อจำกัดที่เคยบังคับให้ใช้ Realtime ของผู้ให้บริการหายไปด้วย เพราะ process ที่รันยาวบน VPS ถือ WebSocket เองได้ ต่างจาก serverless

WHAT DID NOT MOVE

สิ่งที่ไม่เปลี่ยนเลย

  • data-model-v1 ทั้งฉบับ — 21 entity, invariant 22 ข้อ, CHECK constraint, VIEW, state machine ทั้งสาม
  • api-design-v1 §5.1–5.6 — race condition ทั้ง 6 เคสยังใช้ FOR UPDATE และ ON CONFLICT เหมือนเดิม
  • Business Rule ทุกข้อยังถูกบังคับด้วยโครงสร้าง ไม่ใช่วินัยของคนเขียนโค้ด

UNINTENDED WIN

ของแถมที่ไม่ได้ตั้งใจ

  • §3.3 เลือก Realtime ของผู้ให้บริการเพราะ serverless ถือ connection ค้างไม่ได้ — ข้อจำกัดนั้นหายไปพร้อมกับ Vercel
  • กลไกใหม่คือ LISTEN/NOTIFY ยิงเข้า WS ในโปรเจกต์เดียวกัน ยังรักษาคุณสมบัติเดิมไว้คือ event ออกจาก DB โดยตรง ไม่มีทางลืม publish
  • R2 เพดาน realtime และ R10 vendor lock-in ปิดทั้งคู่

STILL OPEN

ยังไม่ตัดสิน

  • กลไก auth ของพนักงานและแอดมิน — เดิมใช้ Supabase Auth ตอนนี้ต้องเลือกใหม่ หลักการแยก 2 กลไกยังใช้ได้
  • Firebase เป็นข้อบังคับของวิชาหรือไม่ — รอถามผู้สอน ดู §9.7
  • ความเสี่ยงใหม่ R13 ภาระ ops · R14 backup ที่กู้ไม่ได้ · R15 VPS เครื่องเดียว
