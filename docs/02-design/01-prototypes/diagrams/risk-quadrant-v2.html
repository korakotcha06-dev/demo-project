ARCHITECTURE · §9.5 · RISK REGISTER REVISED

ความเสี่ยงหลังย้ายมา VPS

การย้ายปิดความเสี่ยงเดิมไปสองข้อ แต่เปิดใหม่สามข้อ และข้อที่หนักที่สุดไม่ใช่เรื่องเทคนิค — เป็นเรื่องว่าใครจะดูแลมันจริง ๆ หลังเปิดร้าน สองจุดที่ทำเครื่องหมายไว้คือข้อที่ผลกระทบรุนแรงที่สุด และทั้งคู่จบที่ข้อมูลหายหรือขายไม่ได้ทั้งร้าน

NEW AND WORST

R14 คือข้อที่ต้องกลัวที่สุด

  • ไม่ใช่ความเสี่ยงเชิงทฤษฎี — เคยเกิดจริงที่ระบบอื่นของ TNM สคริปต์ backup เงียบไปสิบคืนโดยไม่มีใครรู้ เพราะบั๊กใน shell ที่ทำให้ exit code หายไป
  • มาตรการที่ใช้ได้จริงคือ ทดสอบ restore จริง ไม่ใช่ดูว่าไฟล์ถูกสร้าง และต้องมี alert เมื่อ backup ไม่ผ่าน
  • เดิม Supabase ทำให้ฟรี ตอนนี้เป็นงานที่ต้องทำเองและต้องทำก่อนเปิดร้าน

TRADE

ปิดสอง เปิดสาม

  • ปิด — R2 เพดาน realtime · R10 vendor lock-in · R11 เบาลงมากเพราะ VPS ราคาคงที่
  • เปิด — R13 ภาระ ops · R14 backup · R15 เครื่องเดียวไม่มี redundancy
  • R13 กับ R15 คือสิ่งที่ managed service เคยทำให้ฟรี ตอนนี้เป็นราคาที่จ่ายแลกกับการควบคุมเต็มที่

FIDELITY

วิธีอ่านผังนี้

  • 12 จุดในผัง · R2 R10 ปิดแล้ว · R11 ยกออกไปอยู่ในกล่องเพราะเบาลงจนไม่คุ้มพื้นที่
  • ระดับในเอกสารเป็นคำ ไม่ใช่ตัวเลข ตำแหน่งคือการแปลงคำเป็นพิกัด ข้อที่ได้ระดับเท่ากันถูกกระจายเล็กน้อย
  • R3 cold start น่าจะลดลงมากบน process ที่รันยาว แต่ยังไม่ได้ประเมินใหม่อย่างเป็นทางการ ผังนี้จึงยังวางไว้ที่ระดับเดิม
