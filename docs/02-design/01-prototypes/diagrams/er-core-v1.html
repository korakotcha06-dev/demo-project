แกนเงิน — 8 ตารางที่บิลต้องพึ่ง

schema เต็มมี 21 entity ภาพนี้ตัดเหลือเส้นทางเดียวที่เงินเดินผ่าน ตั้งแต่โต๊ะจนถึงการรับชำระ หัวใจอยู่ที่ table_session ซึ่งเป็นทั้งตัวผูกรอบลูกค้าเข้ากับบิล และเป็นแถวที่ทั้งการสั่งเพิ่มและการปิดบิลต้องแย่งล็อกกัน

THE LOCK ROW

ทำไม table_session ถึงเป็นศูนย์กลาง

  • ผูกโต๊ะเข้ากับหนึ่งรอบลูกค้า และหนึ่งรอบมีบิลใบเดียวกับตะกร้าใบเดียว
  • เป็นแถวที่ POST /orders และ POST /bills/{id}/close ต้อง SELECT … FOR UPDATE ทั้งคู่ ดู race-close-bill-v1
  • ปิด session คือสิ่งเดียวที่ทำให้โต๊ะกลับเป็นว่าง ดู table-state-v1

SNAPSHOT

ราคาในบิลไม่ผูกกับเมนู

  • order_item เก็บ name_snapshot และ price_snapshot ไว้ในตัวเอง
  • เจ้าของร้านแก้ราคาระหว่างที่มีบิลเปิดค้าง ยอดบิลเดิมไม่ขยับ — กันความเสี่ยง R8
  • payment เป็น ledger หลายแถวต่อหนึ่งบิล การคืนเงินจึงเป็นแถวใหม่ ไม่ใช่การแก้ของเดิม
