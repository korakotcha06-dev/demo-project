NFR · §7 · DESIGN COVERAGE

NFR 20 ข้อ ออกแบบรองรับแล้วแค่ไหน

แท่งทึบคือจำนวนข้อที่ 02-design รองรับแล้ว ส่วนกรอบจาง ๆ คือจำนวนข้อทั้งหมดของหมวดนั้น หมวดที่ทำเครื่องหมายไว้คือหมวดเดียวที่มีข้อซึ่ง design ยังไม่รองรับเลยถึงสองข้อ และทั้งสองข้อเป็น exit criteria ของ Phase 0 โดยตรง

THREE GAPS

สามข้อที่ design ยังไม่รองรับเลย

  • NFR-06 — หลายอุปกรณ์ล็อกอินบัญชีสถานีเดียวพร้อมกัน 2 ถึง 4 เครื่องโดยไม่เด้งกัน เป็น exit criteria ของ Phase 0 ตรง ๆ ถ้าออกแบบ auth เป็น single-session ต้องรื้อทีหลัง
  • NFR-10 — session อย่างน้อย 12 ชั่วโมง ห้าม auto-logout ระหว่างมีออเดอร์ค้าง
  • NFR-11 — ปลดล็อกด้วย PIN สั้น ห้ามพิมพ์รหัสผ่านเต็ม เพราะมือเปียกจริงหน้างาน

ROOT CAUSE

ทำไมสามข้อนี้ถึงหลุด

  • ทั้งสามมาจาก Business Rule ข้อ 26 ถึง 27 ซึ่งเขียนไว้เองว่าต้องถูกสะท้อนใน architecture และ data model
  • ไม่มี US เป็นเจ้าภาพ จึงไม่เข้า feature tree และไม่มีใครหยิบไปออกแบบ
  • การมีรหัส NFR-xx คือกลไกที่ทำให้เรื่องแบบนี้ถูกจับได้ ไม่ใช่หลุดเงียบอีกรอบ

THE OTHER ZERO

ตัวเลขที่ไม่ได้อยู่ในแท่ง

  • test coverage = 0 จาก 20 ทุกหมวดเท่ากันหมด ยังไม่มี test case สักข้อ
  • ผมไม่ได้วาดเป็นแท่งที่สอง เพราะแท่งศูนย์ทั้งแถวอ่านเหมือนภาพเสีย
  • เลือกใช้แท่งแทน radar เพราะ radar ต้องการ 3 ถึง 5 entity เทียบกันบน 3 ถึง 5 แกน แต่ข้อมูลชุดนี้มี 6 หมวดและมีชุดค่าชุดเดียว
