API DESIGN · §5.3 · RACE CONDITION

ปิดบิลชนกับการสั่งเพิ่ม

แคชเชียร์เห็นยอด 250 บาทบนหน้าจอ ลูกค้ากดสั่งลาเต้เพิ่มอีก 70 บาทในจังหวะเดียวกัน ถ้าไม่มีอะไรกั้น ร้านเก็บเงินขาด 70 บาท และออเดอร์ที่เพิ่งสั่งจะไปผูกกับบิลที่ปิดไปแล้ว ทั้งสองเส้นทางจึงถูกบังคับให้ล็อกแถวเดียวกันก่อนเสมอ

THE MECHANISM

ล็อกแถวเดียวกันทั้งสองทาง

  • POST /orders และ POST /bills/{id}/close เริ่มด้วย SELECT … FOR UPDATE บน visit_session บรรทัดเดียวกัน
  • ใครได้ล็อกก่อนคือผู้ชนะ อีกฝ่ายไม่ถูกปฏิเสธเงียบ แต่ได้ 409 ที่บอกสถานะใหม่
  • close บังคับส่ง expected_total_satang — เท่ากับประกาศว่า "จะเก็บตามยอดที่เห็นอยู่"

TWO OUTCOMES

ผลของแต่ละฝั่ง

  • สั่งเพิ่มชนะ — แคชเชียร์ได้ 409 BILL_CHANGED พร้อมยอดใหม่และรายการที่เพิ่งเข้า ต้องกดยืนยันอีกครั้ง
  • ปิดบิลชนะ — ลูกค้าได้ 409 SESSION_CLOSED และ ตะกร้าต้องไม่ถูกลบทิ้ง
  • force: true ใช้ข้ามออเดอร์ค้างทำเท่านั้น ห้ามใช้ข้ามการตรวจยอด

FIDELITY

ขอบเขตของภาพนี้

  • 4 lifeline · 9 ข้อความ · 1 fragment (เพดาน 5 / 12 / 1)
  • วาดจากข้อความล้วนใน §5.3 ไม่มี mermaid ต้นทาง
  • เส้นทาง force: true และ §8 ข้อ 2 ไม่อยู่ในภาพนี้
