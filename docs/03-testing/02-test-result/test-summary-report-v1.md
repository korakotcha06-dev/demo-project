## 7. รูปแบบการรายงานขึ้น Touch

เขียนตามลำดับนี้เสมอ — **ตัวเลขก่อน ความเห็นทีหลัง**:

1. **ตัดสินได้หรือยัง** และถ้ายัง เพราะอะไร (ประโยคเดียว)
2. **ตัวเลข** PASS / FAIL / BLOCKED / DEGRADED — รวมต้องเท่ากับจำนวนเคสทั้งหมด
3. **บั๊ก S1/S2 ที่ยังเปิด** อธิบายเป็นผลกระทบทางธุรกิจ ไม่ใช่ศัพท์เทคนิค ("เก็บเงินขาดได้" ไม่ใช่ "race condition ที่ §5.3")
4. **ต้องการอะไรจากใคร** — ใคร ทำอะไร แล้วปลดล็อกกี่เคส

ใช้ `/management-talk` ทุกครั้งก่อนส่ง
