## 1. ระดับความรุนแรง

| ระดับ | นิยามในบริบทร้านกาแฟนี้ | ตัวอย่าง |
|---|---|---|
| **S1 Critical** | เงินผิด · ข้อมูลหาย · เปิดร้านไม่ได้ · กฎจ่ายก่อนรับรั่ว | ปิดบิลชนกับสั่งเพิ่มแล้วเก็บเงินขาด · ออเดอร์เคาน์เตอร์เข้าครัวทั้งที่ยังไม่จ่าย |
| **S2 Major** | ฟีเจอร์หลักใช้ไม่ได้ แต่มีทางเลี่ยง | จอสถานีไม่อัปเดตเอง ต้องกดรีเฟรช |
| **S3 Minor** | ใช้ได้แต่ผิดจากที่ออกแบบ | หัวข้อกลุ่มที่ว่างยังแสดงอยู่ |
| **S4 Cosmetic** | ไม่กระทบการใช้งาน | ระยะห่างเพี้ยนเล็กน้อย |

> **S1 ทุกตัวบล็อกการเปิดร้าน** ไม่ว่าจะเจอตอนไหนของรอบทดสอบ

`เปิด` → `กำลังแก้` → `แก้แล้วรอ verify` → `ปิด (verify แล้ว)`

## 3. ตารางบั๊ก

| BUG | พบที่ TC | Req ID | ความรุนแรง | อาการ | ขั้นตอนทำซ้ำ | สภาพแวดล้อม | เจ้าของ | สถานะ | verify เมื่อ |
|---|---|---|---|---|---|---|---|---|---|
| — | *(ยังไม่มี)* | | | | | | | | |

**กติกาการกรอก:**

- **ID เรียงต่อเนื่อง** `BUG-001`, `BUG-002` … ห้ามใช้เลขซ้ำแม้บั๊กจะถูกปฏิเสธ
- **"ขั้นตอนทำซ้ำ" ต้องทำซ้ำได้จริง** — ถ้าทำซ้ำไม่ได้ ให้เรียก `/debug-mantra` ก่อน อย่าเพิ่งบันทึกเป็นบั๊ก · บั๊กที่ทำซ้ำไม่ได้จะถูกปิดโดยอัตโนมัติว่า "ไม่พบ" และเสียเวลาทุกฝ่าย
- **"อาการ" เขียนสิ่งที่เห็น ไม่ใช่สิ่งที่เดาว่าเป็นสาเหตุ** — สาเหตุเป็นงานของคนแก้
- **บั๊กหนึ่งตัวต่อหนึ่งแถว** — เจอ 3 อาการจากสาเหตุเดียว ให้แยก 3 แถวแล้วโยงถึงกัน ไม่ใช่ยัดรวม
- **บั๊กที่ไม่ได้มาจาก TC ไหนเลย** (เจอระหว่างทาง) ให้ใส่ `—` ในช่อง TC แล้ว **เปิด TC ใหม่ตามไปด้วย** — ถ้าเจอครั้งนี้โดยบังเอิญ แปลว่าครั้งหน้าจะพลาด
