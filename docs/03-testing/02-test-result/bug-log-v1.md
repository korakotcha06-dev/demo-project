## 5. บั๊กที่เปิดค้างอยู่จริง vs. งานที่ยังไม่ได้ทำ (เพิ่ม 2026-08-28)

## 6. ข้อสังเกตเรื่อง convention (ไม่ใช่บั๊ก — เพิ่ม 2026-08-28)

พบระหว่างเขียนเทส integration ของ US-25 ในวันเดียวกัน: **`requireAdmin` ปฏิเสธผู้ใช้ที่ไม่ใช่แอดมินด้วยรหัส `401 Unauthorized` ไม่ใช่ `403 Forbidden`** ทั้งที่คนนั้น**ล็อกอินอยู่แล้วจริง** (มี session/cookie ถูกต้อง แค่ไม่มีสิทธิ์ระดับแอดมิน) — ตามความหมายมาตรฐานของ HTTP, `401` ควรสงวนไว้สำหรับ "ยังไม่ยืนยันตัวตน/ยืนยันไม่ผ่าน" ส่วน `403` คือ "ยืนยันตัวตนผ่านแล้วแต่ไม่มีสิทธิ์ทำสิ่งนี้" — เคสนี้ตรงกับนิยามของ `403` มากกว่า

**ทำไมไม่นับเป็นบั๊ก:** พฤติกรรมทำงานถูกต้อง (ปฏิเสธคนที่ไม่มีสิทธิ์จริง ๆ ตาม BR ข้อ 28 — ดู `role-gate.test.ts`) เป็นเรื่อง **ความหมายของรหัสสถานะ (semantic)** ไม่ใช่ฟังก์ชันผิด — แต่ควรเคาะให้ตรงกันทั้งระบบสักครั้ง เพราะถ้าปล่อยไว้ ผู้เรียก API (เช่น frontend ที่จะแยกกรณี "ต้อง login ใหม่" ออกจาก "login อยู่แล้วแต่ไม่มีสิทธิ์") อาจเขียน logic ผิดจากการอ่านรหัสสถานะที่ไม่ตรงความหมายมาตรฐาน — ฝากไว้เป็นข้อเสนอให้ COULSON/BANNER พิจารณาเคาะ convention เดียวทั้งระบบ ไม่ใช่ภาระของไฟล์นี้ที่จะตัดสินใจเอง
