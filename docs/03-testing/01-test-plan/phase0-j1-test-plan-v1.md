## 2. เคสที่ต้องทดสอบด้วยมือ (OKOYE ต้องผ่านทุกข้อก่อนเปิดร้าน)

### 2.1 J1 ครบวงด้วยมือถือจริง 2 เครื่อง

เตรียม: `pnpm seed` แล้วใช้ URL ของโต๊ะที่พิมพ์ออกมา · เปิดบนมือถือจริง **2 รุ่นต่างกัน**
(task กลุ่มงาน A บังคับให้ทดสอบ ≥2 รุ่นก่อนสั่งพิมพ์ QR เต็มจำนวน)

| # | ขั้นตอน | เกณฑ์ผ่าน |
|---|---|---|
| 1 | สแกน QR ด้วยกล้องมือถือ (ไม่ใช่พิมพ์ URL) | เห็นเมนู **ไม่มีหน้ากลาง** · ≤3 วิ บน 4G · ≤5 วิ บน Slow 3G (UX-01) |
| 2 | เครื่อง A และ B เพิ่มของคนละอย่างพร้อมกัน | ทั้งสองเครื่องเห็นของกัน **ภายใน 5 วินาที** โดยไม่กดรีเฟรช (UX-06) |
| 3 | เครื่อง B ดูตะกร้า | รายการของ A มีป้าย "เพิ่มโดยอุปกรณ์อื่น" **ไม่มีชื่อ/ตัวตนใด ๆ** (BR ข้อ 14) |
| 4 | เครื่อง A กดยืนยัน | ตั๋วขึ้นจอสถานี **พร้อมเสียง** · ตัวเลือกทุกตัวปรากฏบนตั๋ว (กันทำผิดสูตร) |
| 5 | เครื่อง B ดูสถานะ | เห็นออเดอร์ที่ A สั่ง ทั้งที่ B ไม่ได้กดยืนยัน |
| 6 | พนักงานกด "เสร็จแล้ว" | ทั้ง A และ B เห็นสถานะเปลี่ยนภายใน 5 วินาที |
| 7 | สั่งเพิ่มรอบสอง | รวมยอดในบิลเดียวกันของโต๊ะ (BR ข้อ 1, 7) |
| 8 | ดูสรุปยอด แล้วปิดบิล | โต๊ะกลับเป็น "ว่าง" **เอง** ไม่มีปุ่มเปิด/ปิดโต๊ะให้กดที่ไหน (BR ข้อ 11) |
| 9 | เครื่อง A สั่งเพิ่มหลังบิลปิด | ได้ข้อความบอกว่าบิลปิดแล้ว + **ทางออก** ให้แจ้งพนักงาน · ตะกร้าไม่หาย |

### 2.4 realtime และเน็ตหลุด

| # | สถานการณ์ | เกณฑ์ผ่าน |
|---|---|---|
| 1 | ปิด WebSocket server (`pkill -f realtime-server`) | ทุกจอสลับเป็น polling **ภายใน 10 วินาที** และ **ขึ้นป้ายให้ผู้ใช้เห็น** — ห้ามนิ่งเงียบ |
| 2 | แก้ข้อมูลระหว่างที่อยู่ในโหมดสำรอง | ข้อมูลยังอัปเดตถูกภายใน 5 วินาที |
| 3 | เปิด WebSocket กลับมา | กลับเป็นโหมดปกติ ป้ายหาย |
| 4 | สลับไปแอปอื่นบนแท็บเล็ตสถานีแล้วกลับมา | กลับเป็นโหมดปกติ **ทันที** ไม่ต้องรอนาที (timer ของแท็บที่ซ่อนถูกหน่วง) |
| 5 | ปิด Wi-Fi ตอนกดยืนยันออเดอร์ | บอกว่า **ยังไม่ได้ส่ง** · ตะกร้าไม่หาย · กดส่งใหม่แล้วไม่เกิดออเดอร์ซ้ำ |

### 2.7 Accessibility baseline (Business Rule ข้อ 23) — ทุกหน้าจอลูกค้า

ตรวจด้วยเครื่องมืออัตโนมัติ (axe / Lighthouse) **ก่อนปิดงาน** ไม่ใช่ตรวจด้วยตาเปล่า

- [ ] ตัวอักษรเนื้อหาปกติ ≥ 16px และ browser zoom 200% เนื้อหาไม่ถูกตัด/ทับกัน
- [ ] contrast ข้อความปกติ ≥ 4.5:1 · ข้อความใหญ่/ไอคอนสำคัญ ≥ 3:1
- [ ] พื้นที่กดฝั่งลูกค้า ≥ 44×44px · ฝั่งสถานี ≥ 48px + ระยะห่าง ≥ 8px
- [ ] ทุกจุดที่สื่อความหมายด้วยสี **มีข้อความหรือไอคอนกำกับ** (สถานะออเดอร์, ของหมด, ว่าง/ไม่ว่าง)
- [ ] อ่านออกในสภาพแสงจ้า/กลางแดด — ทดสอบหน้างานจริง ไม่ใช่ในห้องแอร์
- [ ] ใช้คีย์บอร์ดเดินได้ทุก control และเห็น focus ring ชัด
- [ ] **สลับ `--font-thai` เป็น `Sarabun`** แล้วทั้งระบบต้องเปลี่ยนตาม (design-system §3.5 —
      ข้อกำหนดทางสถาปัตยกรรม ถ้าต้องแก้หลายที่คือผิด)

### 2.8 ภาษาและข้อความ (UX §6)

- [ ] ไม่มีคำว่า session / checkout / submit / error code ในข้อความที่ลูกค้าเห็น
- [ ] **ทุก error มีทางออกเสมอ** — ไม่มีหน้าจอที่บอกแค่ว่าผิดพลาดแล้วจบ
- [ ] ใช้เลขอารบิกทั้งหมด ไม่มีเลขไทย
- [ ] ข้อความ "ค่าความหวานที่เลือกไว้คือ 50%" มองเห็นชัด ไม่ซ่อน (US-43)
