## 0. โจทย์เฉพาะของ J1 — ทำไมเส้นนี้ทดสอบยากกว่าที่คิด

J1 คือ happy path หลักของ MVP และมักถูกมองว่า "แค่ไล่กดตามลำดับ" ซึ่งเป็นความเข้าใจผิด · เส้นนี้มีกลไกสองอย่างที่**พังเงียบ** และจะไม่มีวันถูกจับได้ถ้าทดสอบด้วยคนเดียวหนึ่งเครื่อง:

1. **ตะกร้าแชร์ทั้งโต๊ะแบบ concurrent (Business Rule ข้อ 2 · NFR-05)** — ระบบต้องรองรับหลายคนหลายเครื่องเขียนเข้าตะกร้าเดียวกันพร้อมกัน · **ทดสอบด้วยเครื่องเดียวจะผ่านเสมอ** และบั๊กจะไปโผล่ตอนลูกค้ากลุ่ม 3 คนมานั่งโต๊ะเดียวกันวันเปิดร้าน
2. **สถานะโต๊ะ derive จากเหตุการณ์ออเดอร์เท่านั้น (Business Rule ข้อ 11)** — ไม่มีจุดใดที่พนักงานกดเปลี่ยนสถานะโต๊ะด้วยมือ · การทดสอบที่ถูกต้องคือ **นับจำนวนครั้งที่พนักงานต้องกดอะไรเพื่อให้สถานะโต๊ะถูกต้อง แล้วต้องได้ 0**

เอกสารนี้ยังครอบ **AC แอนิเมชันกำลังชง 4 ข้อของ US-05** ที่อนุมัติ 2026-08-16 ซึ่ง [[test-plan-v1|Test Plan v1]] ยังไม่มีเคสแตะ (TC-010 ทดสอบแค่สถานะ 3 ระดับแบบเดิม)

### 0.1 แปลงคะแนนอารมณ์เป็นตัวชี้วัดที่นับได้

| ขั้นใน J1 | คะแนน | ตัวชี้วัดที่นับได้จริง |
|---|---|---|
| สแกน QR (MoT #1) | **5** | จำนวนหน้าคั่นก่อนถึงเมนู = 0 · เวลาถึงเมนูที่สั่งได้จริง (NFR-01) |
| สั่งเพิ่มรอบสอง | **5** | จำนวน tap จากหน้าสถานะกลับถึงเมนู ≤ 1 · จำนวนครั้งที่ต้องสแกนซ้ำ = 0 |
| รอ/ติดตามสถานะ | **3** | จำนวนวินาทีที่จอนิ่งสนิทหลังกดยืนยัน = 0 (ต้องมีแอนิเมชันทันที) · จำนวนครั้งที่ต้องกดรีเฟรช = 0 |
| ต่อคิวจ่ายเงิน (MoT #2) | **2** | **จำนวนวิธีจ่ายเงินที่ไม่ต้องต่อคิวที่เคาน์เตอร์ = 0** → fail by design (หัวข้อ 5) |

> 🔴 J1 มีขั้นที่ได้ 5 ถึงสองขั้น — **ขั้นที่คะแนนสูงคือขั้นที่เกณฑ์ต้องโหด ไม่ใช่หย่อน** · ถ้าสแกน QR แล้วมีหน้าคั่นแม้หน้าเดียว หรือสั่งรอบสองต้องสแกนซ้ำ นั่นคือการทำลายเหตุผลทั้งหมดที่ฟ้าเลือกร้านนี้ ไม่ใช่ข้อบกพร่องเล็กน้อย

**เกณฑ์ผ่าน:** ขั้น 1–11 และ 13–14 ผ่านครบในการรันต่อเนื่องครั้งเดียว · **ขั้น 12 คาดว่าไม่ผ่าน และนั่นถูกต้อง**
