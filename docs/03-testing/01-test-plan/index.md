# 01 - Test Plan

เก็บ **แผนการทดสอบ (Test Plan)** ที่เตรียมไว้ก่อนลงมือทดสอบจริง เช่น

- Test case / test scenario ของแต่ละฟีเจอร์
- เงื่อนไขและข้อมูลที่ใช้ในการทดสอบ (test data)
- ขอบเขตของการทดสอบ (in scope / out of scope)

อ้างอิงจากข้อกำหนดใน [[../../01-requirements/01-spec/index|01-spec]] และการออกแบบใน [[../../02-design/index|02-design]] ผลของการทดสอบตาม test case เหล่านี้ให้บันทึกใน [[../02-test-result/index|02-test-result]]

**เจ้าของโฟลเดอร์:** OKOYE (Test Analyst & QA Lead) · เขียน/แก้ด้วย skill `/test-design`

## เอกสารในโฟลเดอร์นี้

อ่านตามลำดับนี้:

1. [[test-plan-v1|Test Plan v1 — Phase 0 (MVP)]] — **กลยุทธ์การทดสอบ**: ขอบเขต in/out พร้อมเหตุผล · สภาพแวดล้อมและอุปกรณ์ที่ต้องมีจริง · requirement ที่เคยเขียนเคสไม่ได้และปิดอย่างไร · สิ่งที่ถูกบล็อกอยู่ · **ลำดับการลงมือเรียงตามความเสี่ยง** (ถ้ามี 2 ชั่วโมงให้รัน 9 เคส) · **เกณฑ์ผ่าน-ไม่ผ่านของ Phase 0** · NEED-INPUT ที่ยังค้าง
2. [[test-case-v1|Test Case Specification v1]] — **124 test case** (TC-001…TC-116 + TC-015a/b, TC-016a, TC-055a/b, TC-072a/b/c) ใน 11 suite ทุกแถวผูก requirement ID สืบกลับได้ · ครอบ **26/26 Phase 0 US · 18/18 NFR · 19/19 UX · 10/10 DB invariant · 6/6 race condition · 16/16 error contract**
3. [[test-data-v1|Test Data v1]] — ชุดข้อมูล **D-1 … D-9** ที่ต้อง seed ให้ครบก่อนรันเคสแรก พร้อมเช็กลิสต์ตรวจรับ และเหตุผลว่าทำไมค่าต้องเป๊ะ
4. [[traceability-matrix-v1|Traceability Matrix v1]] — **โครงเอกสาร** ตารางสืบกลับ `requirement → AC → TC → ผลจริง` · ตอบคำถาม *"ถ้าเปิดร้านวันนี้ มีอะไรที่ไม่เคยถูกทดสอบเลยบ้าง"*
5. [[uat-scenario-v1|UAT Scenario v1]] — **โครงเอกสาร** สคริปต์ 8 สถานการณ์ให้เจ้าของร้าน/พนักงาน/คนนอกลองใช้เอง · วัด *ความเข้าใจของคน* ไม่ใช่พฤติกรรมของระบบ

> **โครงสร้างเปลี่ยนเมื่อ 2026-08-16** — เดิม test case กับ test data อยู่ในไฟล์ `test-plan-v1.md` ฉบับเดียว แยกออกเป็น 3 ไฟล์เพราะเป็นคนละ deliverable และแก้คนละจังหวะ (กลยุทธ์เปลี่ยนน้อย · เคสกับข้อมูลเปลี่ยนบ่อย) · **เนื้อหาเคยกมาครบทุกแถว ไม่ได้แก้แม้แต่เคสเดียว**

> **สถานะการรัน (อัปเดต 2026-08-16):** รันได้เต็มรูปแบบ **106** · บล็อกสนิทเพราะ `02-design` ยังไม่ได้ออกแบบ **15** · รันได้แต่ degraded **3** · **รอ Touch = 0**
> 🔶 **TC-072 / TC-072a / TC-072b / TC-072c จะรันได้ก็ต่อเมื่อ COULSON ออกแบบ field ชื่อเล่น + job ล้าง 90 วันเสร็จ** — ตามคำตัดสิน 2026-08-16 เรื่องเรียกชื่อคู่เลขคิว · ระยะเวลาเก็บ (R-1) ปิดแล้ว — ล้างชื่อเป็น `NULL` ทุก 90 วัน แบบ column-level ห้ามลบแถว
> ✅ **ทุก requirement ของ Phase 0 มี test case ครอบครบแล้ว** — US-15 ที่เคยเขียนเคสไม่ได้ ถูกปิดเมื่อ 2026-08-16 (AC ใหม่: เสียงบังคับ · ≤5 วินาที · ดังแม้จอดับ)
> 🔴 **ห้ามรายงานว่า Phase 0 ผ่านการทดสอบ** ตราบใดที่เคสของ US-44, US-45 และ NFR-06/10/11 ยังรันไม่ได้ — ทั้งสี่เรื่องอยู่ใน exit criteria ของ Phase 0 โดยตรง
> 🔴 **ยังไม่มีใครรันเคสแม้แต่เคสเดียว** — โปรเจกต์นี้ยังไม่มีโค้ดแอปพลิเคชัน
