# UAT Scenario v1 — Phase 0 (MVP)

> **สถานะ: โครงเอกสาร — ยังไม่ได้เขียนสคริปต์ครบ** (สร้าง 2026-08-16)
> สคริปต์ให้ **เจ้าของร้านและพนักงานจริงลองใช้เอง** ก่อนเปิดร้าน — ไม่ใช่เคสสำหรับ dev
> เจ้าของ: **OKOYE** · ผู้ทดสอบ: Touch + พนักงานจริง + คนนอกที่ไม่เคยเห็นระบบ

## 1. UAT ต่างจาก test case อย่างไร

| | [[test-case-v1\|Test Case]] | UAT (เอกสารนี้) |
|---|---|---|
| ถามว่า | *ระบบทำตามสเปคไหม* | *ร้านเปิดขายได้จริงไหม* |
| ผู้ทดสอบ | OKOYE / dev | เจ้าของร้าน · พนักงาน · ลูกค้าที่ไม่เคยเห็นระบบ |
| รูปแบบ | เคสรายข้อ แยกกัน | **เรื่องเล่าต่อเนื่อง** ตั้งแต่ลูกค้าเดินเข้าจนจ่ายเงินออก |
| ภาษา | มีศัพท์เทคนิคได้ | **ห้ามมีศัพท์เทคนิคเลย** — ห้ามคำว่า session, endpoint, status, API |
| ตกเมื่อ | ผลไม่ตรงเกณฑ์ | **ผู้ใช้ทำไม่สำเร็จ หรือทำสำเร็จแต่ไม่เข้าใจว่าเกิดอะไรขึ้น** |

> 🔴 **ระบบที่ผ่าน test case ครบ 121 เคส ยังตก UAT ได้** — เพราะ UAT วัดความเข้าใจของคน ไม่ใช่พฤติกรรมของระบบ · ในโปรเจกต์นี้จุดเสี่ยงที่สุดคือ **ลูกค้าเข้าใจผิดเรื่องจ่ายเงิน** (UX-07/UX-08) ซึ่งระบบทำงานถูก 100% ก็ยังพังได้

## 2. สถานการณ์ที่ต้องเขียนสคริปต์

| # | สถานการณ์ | ผู้ทดสอบ | ผูกกับ |
|---|---|---|---|
| **UAT-1** | ลูกค้านั่งโต๊ะ สั่งครั้งเดียว จ่ายตอนกลับ | คนนอก 1 คน ไม่เคยเห็นระบบ | US-01…07 · UX-07 |
| **UAT-2** | ลูกค้านั่งโต๊ะ สั่งเพิ่มอีก 2 รอบ แล้วปิดบิลรวม | คนนอก 1 คน | US-06 · US-18/19 |
| **UAT-3** | ลูกค้าซื้อกลับ สแกน QR เคาน์เตอร์ **จ่ายก่อนรับ** | คนนอก 1 คน | US-28/29 · US-45 · UX-08 |
| **UAT-4** | ลูกค้าไม่มีมือถือ พนักงานคีย์ให้ | พนักงานจริง + คนนอก | US-30 |
| **UAT-5** | นาทีพีค — 3 โต๊ะสั่งพร้อมกัน + 1 เคาน์เตอร์ | พนักงานจริง ≥2 คน | NFR-03/06/07 |
| **UAT-6** | ของหมดกลางวัน — มาร์กหมดแล้วลูกค้ายังสั่งอยู่ | พนักงาน + คนนอก | US-16 · NFR-08 |
| **UAT-7** | เจ้าของร้านเพิ่มเมนูใหม่และเพิ่มโต๊ะ **โดยไม่ให้อ่านคู่มือ** | Touch | US-23 · US-42 · UX-11 |
| **UAT-8** | วันเปิดร้านจริง — ติดป้าย QR แล้วเดินทั้งร้าน | Touch | US-24 · US-44 |

## 3. รูปแบบสคริปต์ (ใช้กับทุกสถานการณ์)

```
### UAT-x — <ชื่อสถานการณ์>

**ใครทดสอบ:** …            **ต้องเตรียมอะไร:** …          **เวลาที่ใช้:** ~… นาที

**บอกผู้ทดสอบแค่นี้:** "<ประโยคเดียว เช่น 'คุณมานั่งร้านนี้ อยากได้ลาเต้เย็น 1 แก้ว'>"
🔴 ห้ามสอน ห้ามชี้จอ ห้ามบอกว่าปุ่มไหน — ถ้าต้องบอก แปลว่าตกแล้ว

**เดินตามนี้แล้วสังเกต:**
1. …
2. …

**ถามหลังจบ (ห้ามถามนำ):**
- "ตอนนี้คุณคิดว่าเกิดอะไรขึ้นกับออเดอร์ของคุณ?"
- "ถ้าจะจ่ายเงิน คุณจะทำยังไง?"
- "มีตรงไหนที่ลังเลหรือไม่แน่ใจบ้าง?"

**ผ่านเมื่อ:** <เกณฑ์ที่วัดได้ เช่น ทำสำเร็จโดยไม่ถามใคร · ตอบคำถามข้อ 2 ถูก>
**ตกเมื่อ:** <อาการที่ถือว่าตก>
```

## 4. เกณฑ์ผ่านรวมของ UAT

| เกณฑ์ | ค่า | ที่มา |
|---|---|---|
| ลูกค้า dine-in เข้าใจว่าจ่ายที่เคาน์เตอร์ตอนกลับ | **≥90%** | UX-07 · TC-076 |
| ลูกค้า takeaway เข้าใจว่าต้องจ่ายก่อน ออเดอร์จึงเข้าครัว | **≥95%** และ **ไม่มีใครเข้าใจผิดว่าส่งไปทำแล้ว** | UX-08 · TC-077 |
| เจ้าของร้านเพิ่มสินค้าได้ในครั้งแรกโดยไม่อ่านคู่มือ | สำเร็จ **≤5 นาที** · success rate **≥90%** | UX-11 · TC-080 |
| ลูกค้าสั่งจบใน | **≤6 tap · ≤90 วินาที** | UX-02 · TC-074 |

> ⚠️ **ถ้าหาผู้ทดสอบไม่ครบจำนวนขั้นต่ำ (10 คนสำหรับ UAT-1/3 · 5 คนสำหรับ UAT-7)** ให้รายงานผลเป็น **indicative** ห้ามรายงานเป็นเปอร์เซ็นต์ที่ผ่านเกณฑ์ — ตัวเลข % จาก 2 คนไม่มีความหมาย
